# GY 경복궁 맵 제작용 Blender MCP 마스터 프롬프트

아래 내용을 Blender MCP에 그대로 전달한다.

---

당신은 모바일 게임용 환경 모델링을 담당하는 Blender 제작 에이전트다. 현재 작업의 목표는 한국의 경복궁을 OVERDARE Studio 프로젝트 `GY`에 가져올 수 있도록, 역사적 특징을 유지하면서도 저사양 모바일에서 실행 가능한 모듈형 3D 맵으로 제작하는 것이다.

## 1. 현재 OVERDARE 프로젝트 상태

- 프로젝트명: `GY`
- 현재 맵은 기본 템플릿 상태이며 경복궁 자산은 아직 없다.
- 기본 바닥은 월드 기준 높이 `Y=0`에 있다.
- 기본 SpawnLocation은 월드 원점 `(0, 0, 0)`에 있다.
- 기존 경복궁 모델, 지형, 커스텀 재질, 게임 스크립트는 없다.
- 따라서 기존 모델을 수정하지 말고 신규 환경 자산 세트를 제작한다.
- 플레이어가 원점에서 시작해 광화문을 바라보고 북쪽의 중심축을 따라 이동할 수 있도록 진입 광장을 확보한다.

## 2. 제작 방향

- 스타일: 역사적 형태를 알아볼 수 있는 `stylized realistic` 모바일 게임 스타일.
- 금지: 판타지 장식, 중국·일본식 요소 혼합, 과도한 현대화, 확인되지 않은 문양 임의 추가.
- 우선순위: 완벽한 고증보다 `경복궁으로 즉시 인식되는 실루엣`, 실제 플레이 동선, 모바일 성능, 안정적인 충돌.
- 실제 자료가 제공되면 그 자료를 최우선으로 사용한다.
- 신뢰할 수 있는 평면도나 사진 자료에 접근할 수 없다면 세부 치수를 임의 확정하지 말고, 알려진 중심축과 건물 관계를 유지한 게임용 근사치임을 결과 보고서에 명시한다.
- 숨겨진 내부 구조는 만들지 않는다. 플레이에 필요한 외부 공간과 통과 가능한 문만 제작한다.

## 3. 전체 배치와 좌표

Blender 장면은 다음 규칙을 사용한다.

- Unit System: Metric
- Length: Meters
- Blender 축: `X = 동서`, `Y = 남북`, `Z = 위`
- 모든 지면의 기준 높이: `Z=0`
- 장면 원점 `(0,0,0)`은 플레이어 시작용 진입 광장의 중심으로 둔다.
- 광화문 중앙은 원점에서 북쪽으로 약 `Y=30m` 떨어진 곳에 둔다. 원점 주변 최소 `20m x 20m`는 건물과 충돌체가 없는 안전한 스폰 공간으로 남긴다.
- 경복궁의 주 중심축은 `X=0`을 따라 북쪽 `+Y` 방향으로 이어지게 한다.
- 광화문, 흥례문, 근정문, 근정전의 중심을 가능한 한 같은 축에 정렬한다.
- 지면 아래로 메시가 내려가지 않게 하고, 모든 건물의 기단 바닥이 `Z=0` 또는 해당 마당 높이에 정확히 닿게 한다.
- 장면에 `GUIDE_NORTH_ARROW`, `GUIDE_ORIGIN_MARKER`, `GUIDE_PLAYER_SCALE_180CM`을 만들어 방향과 크기를 검증한다. 이 가이드는 최종 FBX에는 포함하지 않는다.

## 4. 제작 범위와 단계

한 번에 고밀도 전체 궁궐을 만들지 말고 다음 단계를 순서대로 진행한다. 각 단계가 끝날 때 파일을 저장하고 통계와 문제를 보고한다.

### Phase 1: 플레이 가능한 블록아웃

먼저 아래 핵심 구역을 단순한 박스와 저밀도 지붕으로 구성한다.

1. 진입 광장과 광화문
2. 광화문 뒤 중심 마당
3. 흥례문
4. 근정문
5. 근정전과 월대
6. 중심 동선 양옆의 기본 회랑과 담장
7. 경회루 위치를 보여주는 연못과 저밀도 건물 블록

블록아웃에서 가장 먼저 확인할 것:

- 원점 스폰 공간이 비어 있는가
- 모든 주요 문을 플레이어가 통과할 수 있는가
- 계단, 문턱, 회랑 폭이 모바일 캐릭터 이동에 충분한가
- 주요 건물의 크기 차이와 중심축이 명확한가
- 지면 관통이나 겹치는 메시가 없는가

### Phase 2: 모듈 키트

다음 반복 부품을 별도 모듈로 만든다.

- `MOD_Wall_Straight`
- `MOD_Wall_Corner`
- `MOD_Wall_GateOpening`
- `MOD_Corridor_Bay`
- `MOD_StonePlatform`
- `MOD_StoneStair`
- `MOD_WoodColumn`
- `MOD_WoodBeam`
- `MOD_Railing`
- `MOD_Roof_Straight`
- `MOD_Roof_Corner`
- `MOD_Roof_Ridge`
- `MOD_Roof_EndCap`
- `MOD_Paving_Stone`

반복 요소는 가능한 한 같은 메시와 같은 재질을 재사용한다. 복제 가능한 부품을 건물마다 새 메시로 만들지 않는다.

### Phase 3: 핵심 건물 디테일

다음 순서로 디테일을 추가한다.

1. 광화문
2. 근정전
3. 흥례문과 근정문
4. 회랑과 담장
5. 경회루와 연못

경복궁의 인지도를 만드는 요소를 우선한다.

- 넓게 뻗은 전통 지붕 실루엣
- 처마의 층과 곡선
- 붉은 목조 기둥과 녹색 계열 단청 인상
- 회색 기와와 용마루
- 석조 월대와 넓은 마당
- 중앙 축의 문과 전각 배치
- 경회루의 수면 위 기둥 구조

단청은 작은 입체 장식으로 모두 모델링하지 말고, 대부분 텍스처와 단순한 색 띠로 표현한다. 멀리서 보이지 않는 조각과 기와 한 장 단위의 과도한 모델링은 하지 않는다.

### Phase 4: 최적화와 내보내기

각 구역을 별도 임포트하고 필요할 때 숨기거나 교체할 수 있도록 논리적인 자산 단위로 나눈다.

권장 구역:

- `ZONE_01_Entrance_Gwanghwamun`
- `ZONE_02_Heungnyemun_Courtyard`
- `ZONE_03_Geunjeongmun`
- `ZONE_04_Geunjeongjeon`
- `ZONE_05_Corridors_Walls`
- `ZONE_06_Gyeonghoeru_Pond`
- `ZONE_07_Ground_Paving`

거대한 하나의 메시로 합치지 않는다. 반대로 기와 한 장마다 오브젝트를 분리하지도 않는다. 한 건물 또는 반복 가능한 모듈을 기준으로 적절히 묶는다.

## 5. OVERDARE 성능 제한

다음은 반드시 지켜야 하는 공식 목표다.

- 임포트 가능한 메시 파일 형식: FBX 또는 OBJ. 최종 전달은 FBX를 우선한다.
- 개별 임포트 메시: 최대 `30,000 triangles`를 절대 넘지 않는다.
- 저사양 모바일 목표:
  - 한 화면에 보이는 정점 총합 `70,000 이하`
  - 한 화면의 draw call `70 이하`
  - 한 화면의 512 텍스처 `100개 이하`
- 일반 Performance Guide 상한도 참고한다.
  - FPS 30 이상
  - 화면 전체 mesh triangles 300,000 이하
  - draw calls 200 이하
  - texture memory 150MB 이하
- 작은 반복 소품은 가능하면 메시당 `700 vertices 이하`를 목표로 한다.
- 광화문과 근정전 같은 대표 건물은 여러 최적화된 하위 메시로 나눌 수 있지만, 실제 카메라 한 화면에 보이는 전체 예산을 우선한다.
- 카메라에서 거의 보이지 않는 뒷면, 내부, 바닥 아래 면을 삭제한다.
- 동일 재질을 공유하고, 재질 슬롯 수를 최소화한다.
- 가능한 경우 LOD 세트를 만든다.
  - `LOD0`: 가까운 거리용
  - `LOD1`: 중거리, 삼각형 약 50%
  - `LOD2`: 원거리, 삼각형 약 15~25%
- OVERDARE에서 자동 LOD 연결을 보장할 수 없으므로 LOD는 각각 별도 컬렉션과 별도 FBX로도 내보낼 수 있게 준비한다.

## 6. 메시 품질 규칙

- 모든 오브젝트의 Scale과 Rotation을 적용한다.
- 중복 정점, 겹친 면, 내부 면, 비정상 노멀, 비다양체 메시를 정리한다.
- 최종 내보내기 전에 삼각형 기준 통계를 확인한다.
- 긴 담장과 바닥을 지나치게 잘게 분할하지 않는다.
- 지붕 곡선은 실루엣을 유지하는 최소 세그먼트만 사용한다.
- 작은 장식은 노멀맵 또는 베이스 컬러로 대체한다.
- 얇은 단일 면은 필요한 경우에만 사용한다. 기본적으로 메시 앞면 방향을 올바르게 맞추고 Double Sided에 의존하지 않는다.
- 문 통과 공간에는 보이지 않는 면이나 충돌체가 남지 않게 한다.
- 계단은 시각용 계단과 이동용 단순 경사 충돌체를 분리한다.

## 7. 충돌 메시 규칙

OVERDARE는 `UCX_메시이름` 형식의 충돌 메시를 인식한다.

- 시각 메시와 별도로 단순하고 닫힌 convex collision mesh를 만든다.
- 기본 이름: `UCX_<RenderMeshName>`
- 여러 충돌 조각이 필요하면 `UCX_<RenderMeshName>_01`, `_02`처럼 번호를 붙이되, 각각 완전히 닫힌 메시로 만든다.
- 충돌 메시에는 구멍, 열린 면, 뒤집힌 노멀이 없어야 한다.
- 복잡한 지붕 장식과 보이지 않는 구조에는 충돌을 만들지 않는다.
- 플레이어가 닿는 대상에만 충돌을 둔다.
  - 지면과 마당
  - 월대와 계단
  - 담장
  - 기둥의 단순 범위
  - 출입할 수 없는 문
  - 연못 가장자리
- 통과 가능한 문과 회랑 통로는 충돌 공간을 정확히 비운다.
- 시각용 계단에는 낮은 단차가 있더라도, 충돌은 부드러운 경사로 또는 매우 단순한 계단형으로 만든다.
- 경회루 연못 수면은 기본적으로 충돌 없음으로 둔다. 연못 바닥과 경계는 별도 저밀도 충돌로 만든다.
- 자동 충돌 생성은 정밀하지 않을 수 있으므로 주요 이동 영역은 반드시 수동 UCX 충돌을 사용한다.

## 8. 재질과 텍스처

재질 수를 최소화하고 공유 가능한 atlas 중심으로 구성한다.

권장 공용 재질:

- `MAT_RoofTile_Gray`
- `MAT_Wood_Red`
- `MAT_Dancheong_Green`
- `MAT_Stone_LightGray`
- `MAT_Wall_OffWhite`
- `MAT_Ground_Stone`
- `MAT_Water_Simple`

텍스처 규칙:

- 기본 해상도 `512 x 512`.
- 광화문과 근정전의 대표 atlas만 필요할 경우 `1024 x 1024`까지 허용하되 사용 수를 최소화한다.
- PNG 또는 TGA를 사용하며 파일당 15MB를 넘지 않는다.
- 프로시저럴 노드만 사용하지 말고, 최종 결과를 이미지 텍스처로 베이크한다.
- Base Color가 조명 없이도 형태와 색 구분을 유지하도록 한다.
- 고급 셰이더에 의존하지 않는다.
- Normal과 Roughness는 효과가 명확한 표면에만 사용한다.
- 동일 계열 건물은 atlas를 공유한다.
- 파일명, 오브젝트명, 재질명은 영문 ASCII와 숫자, 밑줄만 사용한다.
- UV는 atlas 영역 밖으로 불필요하게 벗어나지 않게 하고, 텍스처 번짐 방지를 위한 padding을 확보한다.

## 10. FBX 내보내기

- FBX를 기본 포맷으로 사용한다.
- 구역 또는 모듈별로 개별 FBX를 만든다.
- 변환 적용 후 내보낸다.
- 장면 단위는 Meter를 유지하고, OVERDARE Import의 `Scale Unit`을 `Meter`로 선택할 수 있도록 한다.
- 최종 임포트에서는 `World Up = Top`을 사용하고, 방향이 반대면 `World Forward`만 조정할 수 있도록 북쪽 가이드를 기준으로 방향을 기록한다.
- 피벗은 다음 기준을 사용한다.
  - 건물: 지면에 닿는 중앙 하단
  - 담장/회랑 모듈: 스냅하기 쉬운 끝점 또는 중앙 하단
  - 전체 구역: 장면 원점과 관계를 보존할 수 있는 기준점
- 전체 배치를 그대로 가져오는 파일과 개별 편집용 파일을 분리한다.
  - `GY_Gyeongbokgung_MasterLayout.fbx`
  - `GY_ZONE_01_Entrance.fbx` 등 구역 파일
  - `GY_MOD_Wall_Straight_A.fbx` 등 모듈 파일
- 내보내기 전에 각 파일이 30,000 triangles 이하인지 자동 검사한다.

## 11. 자동 검증 항목

Blender에서 가능한 검증을 실행하고 결과를 표로 보고한다.

- 오브젝트별 vertices / triangles
- 재질 슬롯 수
- 사용 텍스처와 해상도
- 적용되지 않은 transform
- 음수 scale
- 비정상 노멀
- non-manifold 또는 열린 충돌 메시
- 중복 오브젝트와 중복 면
- 지면 아래로 내려간 메시
- 원점 스폰 안전 구역 침범
- 문 통과 폭과 높이
- 각 FBX의 예상 파일 크기
- 각 구역의 LOD0, LOD1, LOD2 통계

검증 실패 항목을 숨기지 말고 수정하거나 결과 보고서에 명확히 남긴다.

## 12. 작업 방식

1. 먼저 현재 Blender 파일을 검사하고 기존 작업물이 있으면 삭제하지 말고 별도 컬렉션에 보존한다.
2. `GY_GYEONGBOKGUNG_ROOT`와 가이드부터 만든다.
3. Phase 1 블록아웃을 완성한다.
4. 블록아웃 렌더 또는 뷰포트 스크린샷을 동서남북과 플레이어 시점에서 생성한다.
5. 중심축, 스폰 공간, 통과 폭, 전체 크기, 예상 성능 통계를 보고한다.
6. 그 다음 모듈과 디테일 단계로 진행한다.
7. 각 단계 완료 후 `.blend` 파일을 저장한다.
8. 최종적으로 FBX, 텍스처, 통계 보고서, 임포트 안내서를 한 폴더에 정리한다.

## OVERDARE Studio에서의 후속 확인 목록

Blender 작업물을 가져온 뒤 Studio에서 다음을 확인한다.

1. FBX Import의 Scale Unit을 Meter로 선택한다.
2. 광화문 앞 광장과 기본 SpawnLocation이 안전하게 연결되는지 확인한다.
3. 모델 지면이 Baseplate 상단 `Y=0`에 맞는지 확인한다.
4. 모든 주요 문, 계단, 회랑을 캐릭터가 통과할 수 있는지 확인한다.
5. 문과 계단의 UCX 충돌이 시각 메시와 맞는지 확인한다.
6. Performance Guide에서 화면 내 vertices, triangles, draw calls, texture memory를 확인한다.
7. 문제가 생기면 전체 자산을 다시 합치지 말고 해당 구역 또는 모듈만 수정해 재임포트한다.
