
## 9. 잎 검은 판의 진짜 원인과 3차 판 (2026-09-06)
- Studio 는 MeshPart 텍스처 알파를 **전혀 쓰지 않는다**. 1024² 여부·Glass·DoubleSided 전부 무관 (2차 판 프로브로 확정). 산옥 소나무의 검은 배경도 같은 원인 — 그쪽은 PIL RGBA resize 가 알파 0 영역 RGB 를 검정으로 만든 아틀라스였다.

- Studio 에러 팝업: 업로드 직후 에셋을 참조하면 다운로드 3회 실패 후 기본 메시로 캐시된다. 임포트 후 몇 분 대기 / 재시작 후 -Resolve.

## 11. 산벽 "커튼" — Studio 의 음수 bbox 중심 Y 오배치 (2026-09-06 밤)
- 사용자 지적 "바닥 하나당 180도 돌려짐/옆으로 돌려짐" 의 실체: 산벽 6장이 안쪽 가장자리에서 수직 커튼(스커트가 지상으로 솟음)처럼 보였다. 타일·나무는 정상.
- 실측: N1 을 −14.16 m 내리니 정상 언덕, −32.7 m 는 너무 낮음. −14.16 = 2×|bbox 중심 z(−7.08 m)|. 즉 **Studio 39.1 은 bbox 중심 Y 가 음수인 메시를 |중심 Y| 부호를 뒤집어 놓는다**(중심이 원점 위인 타일·나무는 정상).
- 조치: `sgk_placements._static_pos` — 중심 Y<0 이면 CFrame Y = 3·중심Y (NEG_CENTER_FIX). 산벽 6 + 물(−0.42 m) 적용, -Apply 완료. 4면 산벽 정상 확인.
- 부수: 서쪽 산벽 너머로 보이는 거대한 회색 줄무늬 판은 산옥(JSN, X≈−63000) 쪽 물체 — 같은 버그로 솟은 스커트로 추정. 산옥 쪽도 같은 보정이 필요할 수 있다.
- 실험 중 지형 타일 각자 180° 회전(TILE_YAW_DEG)은 맵을 깨뜨려 0 으로 되돌림. 타일 배치·방향은 레이아웃과 일치(빨강/파랑 큐브 축 테스트로 확인: 화면 왼쪽=+X).

## 12. 진짜 원인: Studio 는 메시 내용을 Y축 180° 돌려 그린다 (2026-09-06 밤, 최종)
- 허공에 타일 12 사본을 띄우고 +X(빨강)·+Z(파랑) 큐브를 놓고 찍음: FBX 원본의 절벽(원본 −X, +Z 쪽)이 Studio 에선 +X, −Z 쪽에 나온다 = **내용이 Y축 180° 회전**. 산옥부터 쓰던 Z=+y 배치는 거울상(det −1)이라 이걸 X 반전으로만 남겼고, 산벽·타일마다 "뒤집힌" 것처럼 보였다(사용자 지적이 맞았다).
- 최종 규칙: `L.to_engine` = (x, z, **−y**), yaw = +rot_z, 그리고 **모든 MeshPart yaw 에 +180 (`MESH_YAW_FIX`)**. 콜리전 Part 는 메시가 아니므로 180 없이 Z=−y 만. 스폰 Z 부호 반전.
- 11절의 "음수 bbox 중심 Y 오배치" 는 오진. Studio 는 CFrame 에 bbox 중심을 놓는다(음수 Y 포함). `NEG_CENTER_FIX=False`.
- 결과: 산벽 4면 완만한 언덕, 정자가 석축 위에·다리가 물 위에 정확히 놓임, x=0 경계 연속. `-Apply` 완료(Lua 변경 없음).
- 다른 맵(산옥·경복궁·화성)도 같은 파이프라인이면 내용이 X 반전된 채 배치돼 있을 가능성이 크다. 재배치 시 같은 규칙 적용.
