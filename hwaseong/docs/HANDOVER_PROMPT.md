# 1. [먼저 할 것] 회전을 0으로 되돌려라 — 폐가 현상의 원인

## 1-1. 측정된 사실

189개 MeshPart 전부가 `CFrame.Orientation = (0, -180, 0)` 이다. **서로 다른 값이 딱 한
종류**다. 반면 위치와 크기는 완벽하다:

```
Orientation 분포        (0, -180, 0) → 189 / 189      ← 틀렸다
위치 vs 매니페스트      최대 어긋남 2.4 cm            ← 정상
Size / (2 × UnitExtent) 189개 전부 1.000              ← 정상
MeshId / TextureId      빈 것 0개                     ← 정상
점유 범위               X 42,800~80,000 / Z ±19,200   ← 정상
```

## 1-2. 왜 틀렸나

**이 맵은 회전이 이미 메시 정점에 구워져 있다.** 익스포터(`export_overdare.py`)가
오브젝트마다 `matrix_world` 를 정점에 적용해서 내보낸다. 그리고 임포터는 각 메시를
**자기 bbox 중심**으로 재중심화한다.

그 상태에서 Y 180° 를 주면 **조각 하나하나가 제자리에서 뒤집힌다.** 지붕 조각이
이웃과 반대로 돌아가고, 서까래가 바깥을 향하고, 조립이 통째로 흩어진다.
그게 지금 화면에서 폐가처럼 보이는 것의 정체다.

`(0,-180,0)` 은 다른 맵(JSN_Sangok)의 보정값이다. 그 맵은 마스터 에셋을 인스턴싱해서
배치하므로 회전을 CFrame 이 정하지만, **화성은 그 방식이 아니다.**

## 1-3. 고치는 법

189개 전부 `CFrame.Orientation` 을 `{X:0, Y:0, Z:0}` 으로 바꾼다.
**위치와 Size 는 손대지 마라.** 재발행도 재익스포트도 필요 없다. 되돌릴 수 있는 작업이다.

**부재 하나가 여전히 틀어져 보여도 그것만 따로 돌려서 맞추지 마라.**
좌표계 오류를 가려서 다음에 같은 문제가 다시 난다. 틀어진 게 있으면 보고해 달라.

## 1-4. 확인

고친 뒤 `game.screenshot` 으로 장안문 쪽을 한 장 찍어 달라. 볼 것:

| | 기대 |
|---|---|
| 옹성(반원형 성벽) | 성 **바깥**(도시 쪽)으로 튀어나온다 |
| 문루 지붕 | 처마가 사방으로 뻗고, 조각이 갈라져 있지 않다 |
| 한옥 지붕 | 기와가 한 면으로 이어진다 |

# 2. [그다음] 맵을 절반 크기로 줄여라

지금 화성이 **372 × 384 m** 라 같은 레벨의 다른 맵보다 크다. **선형 0.5배**로 줄인다.

## 2-1. 변환

기준점(피벗)은 **맵 중심이자 지면 높이**다:

```
PIVOT = (X 61400, Y 0, Z 0)
S     = 0.5

새 위치 = PIVOT + (기존 위치 − PIVOT) × S
새 크기 = 기존 크기 × S
Orientation 은 그대로 (1장에서 0으로 만든 값)
```

**세 가지에 전부 똑같이 적용한다:**
1. `Hwaseong Place` 의 MeshPart 189개 (`CFrame.Position` + `Size`)
2. `Hwaseong Collision` 의 993개 (`CFrame.Position` + `Size`) —
   **빼먹으면 충돌면이 지형에서 뜨거나 파묻혀 못 걷게 된다**
3. `Arena_Bound_*` 4개 (`CFrame.Position` + `Size`)

## 2-2. 끝난 뒤 나와야 하는 값

| | 지금 | 절반 후 |
|---|---|---|
| X | 42,800 ~ 80,000 (372 m) | **52,100 ~ 70,700 (186 m)** |
| Y | −1,189 ~ 2,211 | **−595 ~ 1,106** |
| Z | −19,200 ~ 19,200 (384 m) | **−9,600 ~ 9,600 (192 m)** |

이 값과 다르면 피벗이나 적용 범위가 틀린 것이다.

가장 가까운 이웃은 `Changdeokgung Place` (X 27,000~33,000) 이고, 절반 후 여유가
**191 m** 로 늘어난다. 다른 맵과 겹치지 않는다.

## 2-3. 알고 하는 선택이다

위치와 크기를 같이 줄이므로 **건물도 실제로 절반이 된다** — 문루가 30 m → 15 m,

0.45 는 멀쩡하고 0.30 은 갈린다**). 그 수정이 JAM·SBK·HPR·VEG 에는 적용되지 않았다.

1. **1장을 고친 뒤에도 표면이 갈려 보이나?** 이게 제일 중요하다.
   회전만 고쳐서 해결되면 3장은 덮어도 된다.
2. 오버데어가 임포트한 메시에 **LOD·최적화를 돌리나?** 느슨한 면을 흩뜨리는 단계가
   어디인지 아는가. 끌 수 있는 속성이 있나.
3. 끌 수 없다면 재발행이 유일한 답인가. **발행은 되돌릴 수 없어서**
   JAM 19 + SBK 8 + HPR 2 + VEG 6 = 35개 파일을 다시 올려야 한다.
   같은 이름으로 다시 올렸을 때 기존 것과 안전하게 구분하는 방법이 있나.
4. 면/껍질 비가 어느 정도면 안전한가. 20 이상이면 되나, 완전히 하나로 붙어야 하나.
5. 재발행 전에 **한 개만 갈아끼워 검증**할 방법이 있나.

블렌더 쪽 재베이크는 이쪽에서 바로 돌릴 수 있다. **판단만 주면 된다.**

# 4. 좌표 규약 — 이 맵은 JSN_Sangok 과 다르다

JSN_Sangok 명세서를 그대로 적용하면 안 된다. **네 가지가 다르다.**
1장의 사고가 바로 이걸 놓쳐서 났다.

| | JSN_Sangok | **화성** |
|---|---|---|
| X 축 | `X = bx * 100` | 같음 |
| Y 축 | `Y = bz * 100` | **`Y = bz * 100 + 5000`** (FLOOR_Y) |
| Z 축 | `Z = -by * 100` | 같음 |
| 회전 | `M·R_b·Mᵀ` → `to_euler('ZXY')` + 월드 Y 180° 보정 | **`Orientation = (0,0,0)` 예외 없음** |
| 피벗 | 마스터가 바닥 중앙이라 로컬 up 으로 h/2 올림 | **각자의 bbox 중심 그대로. 올리지 않는다** |
| 원점 델타 | `OFFSET = -60000` (X 만) | **ΔX −58000 / ΔY −5000 / ΔZ 0** |

- **Size 는 cm 실치수다** (백분율 아님). `UnitExtent` 는 절반값이므로
  `Size = 2 × UnitExtent` 면 배율 1. 이건 두 맵이 같다.
- `UnitExtent.Z` 가 음수로 나오는데 **부호 규약이고 정상**이다. 비율은 절댓값으로 본다.
- ΔX 가 −58000 인 이유: 레벨에 있던 `PLACE NEW MAP CENTER HERE` 표지판(X 50000)을 따라
  −70000 을 쓰면 맵 서쪽 끝이 X 30,800 까지 내려와 **창덕궁(27,000~33,000)과 22 m 겹친다.**
  **이 델타는 이미 배치에 반영돼 있다. 다시 더하지 마라.**

# 6. 안전 규칙

- **발행된 에셋을 다시 올리지 마라.** 중복 발행이고 되돌릴 수 없다.
  재발행이 답이면 **먼저 말하고 파일 목록을 확정한 뒤** 진행한다.
- **`level.publish` 를 부르지 마라.**
- **플레이 중에 편집하지 마라** — `game.stop` 먼저.
- **매 단계 전에 백업** — `%USERPROFILE%\Desktop\ovdr_backup\hwaseong_<단계>.ovdrjm`.
  되돌리기는 파일 복사 → `level.apply` → `level.save.file`. 백업이 신선한지 확인하고 쓴다.
- **`.ovdrjm` 은 UTF-16LE + BOM.** 전체를 `ConvertFrom-Json`/`ConvertTo-Json` 왕복시키면
  데이터가 훼손된다. **국소 문자열 치환만** 한다.
- **`.ps1` 은 UTF-8 BOM 필수.** 없으면 PS 5.1 이 949 로 읽어 한글이 깨지고
  `Missing closing '}'` 같은 엉뚱한 파서 에러를 낸다.
- **작업 대상 밖의 인스턴스를 건드리지 마라** (0장 표 참조).
- 배치는 되돌릴 수 있고 **발행만 되돌릴 수 없다.**
